## 4. 多会话协作规范（红线）

1. **认领流程**：读本看板 → 选「未认领」且依赖已合并的条目 → 在 tool_box 领号（读 `tasks/next_id.txt` → 写回 +1 → **立即独立提交**；计数器非原子，若发现重号，看板先登者优先，后登者改号并修正任务文件）→ 复制 `tasks/_TEMPLATE.md` 建任务文件 → 回填本看板（会话/任务号/分支）→ 开工。
2. **并行隔离**：每车道在 french-learner 仓用 `git worktree`（`scripts/worktree.bat <车道名>`）建独立目录与 `feature/<版本>-<短名>` 分支开发；**禁止多会话共用主工作区直接改代码**。tool_box 的任务文件体量小，可共用工作区，冲突概率低。
3. **文件边界**（跨边界改动须在看板备注说明理由）：
   - 新端点一律写 `backend/routers/<feature>.py`，不进他人模块；公共工具函数进 `shared/` 需两车道以上使用
   - 新表在自己模块 init 内 `CREATE TABLE IF NOT EXISTS`，不动 `db.py` 公共区
   - 前端只动 `frontend/js/<feature>.js` 与 `index.html` 自己的挂载点
   - `styles.css` 按功能前缀分段（`.today-` / `.listen-` / `.pron-` / `.grammar-`），不重排他人段落
   - `ROADMAP_DEFS` 只由集成会话点亮（改 status/date + 重启），开发分支不改
4. **集成合并门**：车道完成 → 状态置「待集成」→ 集成会话在主工作区合并 → 跑 `start.bat` 冒烟 + 该版本关键端点 → 合并 main → 点亮路线图 → 任务归档。
5. **每版本收尾同步**（归档时执行）：本看板更新 + `tasks/` 归档 + 两张地图（`docs/project_content.md` / `docs/data_content.md`）同步 + `docs/lessons.md` 沉淀（有则写）。
6. **方案确认环节不豁免**：每个版本开工前，认领会话仍须按 AGENTS.md 第 3 步向用户提交该版本的落地方案，确认后才写代码（本总纲确认的是版本划分与并行机制，不代替单版本方案确认）。

## 5. 各版本详案

### v2.2 第一级台阶（车道 A · Wave 1）

- **目标**：真正零基础用户从打开产品到说出第一句法语，全程不断档。
- **关键改动**：定级题库扩 A1 档（A1/A2/B1/B2 四档，题目 12→约 24，算分组适配最低档落位）；A1 内容带手写第一批（读音规则衔接 → 高频 300 词 → 基础句型 être/avoir/疑问/否定 → 6–10 篇 A1 场景短文 + 2 个 A1 对话场景）；onboarding 落 A1 自动进「台阶路径」（读音→首词→首句跟读）。
- **验收草案**：零基础新账号从进入到完成首句跟读 ≤10 分钟无断档；A1 语料 ≥6 篇全部通过校验；定级四档 QA 全通过。

### v2.3 读不完的书（车道 B · Wave 1）

- **目标**：语料 21 → 200+ 篇（A1–B2 各约 50），内容供给不再依赖手写。
- **关键改动**：新增 `content_pipeline/` 三件套——生成器（GLM 按 `texts.json` 同 schema 约束生成，主题×场景×等级矩阵驱动的需求队列）/ 校验器（开源 CC 词频表打底，自动算生词覆盖率 i+1 目标 95–98%、句长分布、等级漂移，不达标自动打回重生成）/ 审校台（轻量 Web 页，人工通过/否决/改后通过，**人审是入库唯一通道**）；edge-tts 音频批量预生成（多音色、可断点续跑）；`seed_input.py` 扩展批量同步。
- **验收草案**：管线端到端跑通；入库 ≥200 篇且 100% 经人审；i+1 推荐池每等级 ≥40 篇；词频表许可合规记录在案。

### v3.0 每天十五分钟（车道 A · Wave 2，依赖 v2.2+v2.3）

- **目标**：自由探索变成「今天学什么」的引导闭环，留存机制有内容可转。
- **关键改动**：「今日」成为首页第一视图（到期复习 N 词 + i+1 输入 1 篇 + 对话 1 场景 ≥5 轮，任务从到期调度与 recommend API 自动生成）；游戏化内核（经验值/等级曲线、每日任务链、连续天数，挂接现有成就与签到机制不另起炉灶）；呀呀 IP 陪伴感第一期（形象随等级/连续天数有状态变化，CSS 绘制零素材依赖；断签不惩罚）。
- **验收草案**：新用户次日回访有明确待办；任务完成→经验→成就→路线图点亮全链路落库。

### v3.1 耳朵开口（车道 B · Wave 2，依赖 v2.3）

- **关键改动**：听力模式（分级音频 + 变速播放 0.75/1.0/1.25 + 精听模式听写填空、逐句复听）；真实语速适应（口语缩略形文本如 `je ne sais pas`→`j'sais pas` + 多音色多语速变体）；音频全部由 v2.3 批量线供给；听力记录入画像。
- **验收草案**：三功能可用；每等级听力素材 ≥20 段；精听完成记录入库进画像。

### v3.2 发音教练（车道 C · Wave 1）

- **关键改动**：跟读流（听标准音 → 录音 → Whisper 转写 + 词级时间戳 → 与目标句对齐）三维评分（内容命中率 / 流利度·语速停顿 / 语速稳定度）+ 中文反馈指出哪个词没发出来；接口预留路线 B（强制对齐 GOP 音素级评分）本期不实现；发音挑战模式进每日任务池（挂 v3.0）。
- **验收草案**：跟读打分端到端 ≤3s 返回；好/中/差录音实测三维分有区分度；低置信不误判（沿用 ASR 三道门控）。

### v3.3 语法的针脚（车道 B · Wave 2，依赖 v2.3）

- **关键改动**：显性语法微卡约 40 个（性数配合、动词变位、时态选择等）；嵌入两处——阅读中生词所在句命中语法点→附微卡入口，复习流按 recast 错误画像推语法卡；同类 recast 错误第 3 次出现→自动推对应语法微卡。
- **验收草案**：40+ 微卡入库；两处嵌入触发正确；recast 模式识别准确率抽检。

### v4.0 说得出口（车道 A · Wave 3，依赖 v3.0 数据积累）

- **关键改动**：口语四维体检报告（数据全部来自既有积累：**流利度**=ASR 词级时间戳算语速/停顿、**准确度**=recast 触发率趋势、**复杂度**=词汇/句式多样性、**互动性**=轮次维持）→ 四维雷达图 + CEFR 口语参考档；定级升级（题库扩至约 60 题四档，按答题情况跳题的简化 CAT；3 个月定期重测提醒）；以四维数据标定「零基础→B1 达成」内部判据并文档化，产品内诚实展示 B2 需真人实践的边界。
- **验收草案**：体检报告可生成且四维有数据来源说明；自适应定级与全量测试结果偏差可解释；B1 判据文档化。

### v4.1 口袋里的呀呀（车道 D · Wave 4）

- **关键改动**：响应式布局 + PWA（manifest + service worker，原生 JS 零构建路线不变）；部署简化（启动脚本收敛单入口、语音服务按需拉起；局域网访问）；**明确不做**：公网 SaaS、多用户账号体系（面客商业决策时另立项）。
- **验收草案**：手机浏览器完成一次完整学习闭环（复习+阅读+对话）；PWA 可安装；真机验收。

## 6. 风险与限制

1. **人审是产能瓶颈**：200 篇语料的人工审校是真实工时，可分批入库，不追求一次到位。
2. **词频表选型**：需 CC 许可开源法语词频表；找不到合规源则校验器降级为句长+生词率启发式。
3. **TTS 批量耗时**：edge-tts 走网络，200 篇×逐句预计数小时，须做成可断点续跑的后台任务。
4. **发音评分路线 A 天花板**：评不了音素级准确性（u/ou 可能漏判），路线 B 接口预留但引入 torch 系依赖，非承诺项。
5. **领号计数器非原子**（历史重号 0051/0052/0056）：缓解 = 领号后立即独立提交 + 看板先登优先 + 重号即改；根治需文件锁，另行立项。
6. **战线长**：8 版本按波次推进，每版本独立验收归档，随时可停在任意版本不留半成品；集成门保证 main 永远可运行。
