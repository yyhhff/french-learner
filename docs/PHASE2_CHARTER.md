## 1. 阶段二章程

### 1.1 愿景延续

阶段一完成了"重述式 AI 口语陪练"纵向切片（4 场景、4 条本地规则、FastAPI+SQLite、浏览器语音与神经 TTS）。阶段二在**不改变产品愿景与理念**的前提下，沿两条主线纵深推进：

> **愿景（延续）**：让中文用户像婴儿一样自然地习得法语，以可负担的成本达到 B2（外派可用）水平。
> **理念（延续）**：婴儿的体验 + 成人的引擎 + 考级的靶心。
> **核心差异化（延续并强化）**：重述式纠错——用户说错时 AI 顺着语义自然重述正确说法并继续对话，不打红叉。

阶段二的两条主线分别回应理念的两面：

- **主线 A（成人的引擎）**：让重述从"4 条本地规则"升级为"LLM 驱动的任意错句自然重述"，使核心差异化从演示级走向可用级。
- **主线 B（婴儿的体验）**：落地"靠可理解输入习得"——提供 i+1 分级短文/对话 + 音频 + 生词标注，让用户像婴儿一样在可理解语境中吸收语言。

### 1.2 阶段二可验收目标

将 A+B 双主线拆解为可度量、可验收的目标。以下阈值为本阶段验收基线，最终字段与接口以架构契约 v2 冻结版本为准。

**主线 A — 对话智能化（重述全覆盖）**

| 编号 | 目标描述 | 量化验收指标 |
|------|----------|--------------|
| A1 | 任意错句重述覆盖 | 建立覆盖 ≥ 6 类常见语法错误（冠词/性数配合/时态/介词/语序/动词变位）的评测集；LLM 模式下错句被识别并自然重述的**覆盖率 ≥ 90%** |
| A2 | 重述正确率 | 评测集上重述**正确率 ≥ 95%**（重述句法语正确、语义贴合原意、不过度纠错） |
| A3 | 不打红叉原则 | 所有纠错响应 **100%** 为自然重述，`recast_of` 正确回填；零"红叉式"否定、零扣分、零直接语法说教 |
| A4 | 降级可用性 | 无 key 或调用失败时 **100%** 自动回退本地规则模式，不向前端抛 500；降级态在响应/日志中明确标识 |
| A5 | 推理延迟 | 单轮重述 P95 响应时间 ≤ 3 秒（glm-4-flash），超时按 A4 降级 |

**主线 B — i+1 可理解输入流**

| 编号 | 目标描述 | 量化验收指标 |
|------|----------|--------------|
| B1 | 等级覆盖 | 输入流覆盖 **A2 / B1 / B2** 三个等级，按 i+1 原则（基于用户当前等级推送高一级可理解输入）组织 |
| B2 | 语料篇数下限 | 每个等级 ≥ **6 篇**，三等级合计 ≥ **18 篇**（正文 + 中文译文 + 音频 + 生词标注四要素齐备） |
| B3 | 生词标注 | 每篇正文标注生词 ≥ **5 个**，每词含释义、词性、CEFR 等级；标注可对应到词卡/复习链路 |
| B4 | 可理解性门槛 | 每篇正文的"已知词 + i+1 级词"覆盖率 ≥ **95%**，由内容角色依规范自评并经测试抽检 |
| B5 | 音频可用 | 语料音频 100% 可播放，采用神经语音（edge-tts），杜绝"le 读成字母"式缺陷；不支持浏览器有文字兜底 |

**共性目标**

| 编号 | 目标描述 | 量化验收指标 |
|------|----------|--------------|
| C1 | 六角色三波协同 | PM/架构师/后端/前端/测试/内容六角色全部就位并按三波计划履职 |
| C2 | 独立 QA | 阶段二测试由测试角色**独立出具报告**，非开发自报；P0 缺陷 = 0 |
| C3 | 契约一致 | 架构契约 v2 与实现零字段偏差；前后端以契约为唯一依据 |

### 1.3 阶段二成功标准

1. **功能成功**：主线 A 的 A1–A5、主线 B 的 B1–B5 全部达标，端到端跑通"任意错句自然重述"与"分级输入流可理解输入"两条链路。
2. **体验成功**：核心差异化（重述式纠错）在 LLM 模式与降级模式下均表现自然；输入流音频与生词标注可用、无"字母朗读"等缺陷。
3. **质量成功**：关键路径 P0 = 0；独立测试报告出具；契约一致性与重述/可理解性指标达标。
4. **交付成功**：M5–M7 按期达成，交付物齐备且可独立验收，章程、架构契约 v2、代码三者一致。
5. **合规成功**：语料/词库版权来源清晰、许可证可审计，商业化前无 CC 非商用（NC）违规风险；异常与降级路径完备。

### 4.2 架构师

- 2.1 设计架构契约 v2：GLM 接入与降级契约（`GLM_API_KEY` 注入、OpenAI 兼容端点、模型参数、超时/重试）

- 3.1 实现 GLM 重述引擎（LLM 模式 + 本地规则降级，接口隔离）

- 3.6 编写单元测试与接口自测（覆盖 A1–A5、B1–B5 可测项）

### 4.4 前端

- 4.1 实现输入流界面：A2/B1/B2 分级浏览、正文阅读、音频播放
- 4.2 实现生词标注交互与"点击查看释义/加入复习"链路
- 4.3 优化对话界面：重述卡片渲染优化、等级/输入流入口整合
- 4.4 音频兼容性降级（不支持浏览器提供文字兜底）与神经语音播放

### 4.5 测试（独立 QA）

- 5.1 制定阶段二测试计划与独立验收用例集
- 5.2 覆盖重述评测集（≥ 6 类语法错误、覆盖率/正确率验证）、降级路径、输入流完整性与音频、浏览器兼容性、回归

## 6. 风险登记册

| 编号 | 风险描述 | 类别 | 等级 | 影响 | 缓解措施 |
|------|----------|------|------|------|----------|
| R1 | 智谱 GLM key 缺失或额度耗尽，重述功能不可用 | 技术/依赖 | **高** | 核心差异化功能失效，联调与交付阻塞 | 强制"有 key / 无 key"双态设计；无 key 或额度失败 100% 自动降级本地规则且不抛 500；key 经 `GLM_API_KEY` 环境变量 + `.env.example` 注入，绝不入库；额度/失败写日志并告警；降级态明确标识 |
| R2 | LLM 推理成本与延迟随用量增长，体验卡顿、成本超预算 | 成本/性能 | **高** | 单位经济模型不成立、单轮响应 P95 超标 | 选用轻量模型 `glm-4-flash`；上下文仅取最近 10 轮；高频结果缓存；设用量配额与预算告警；监控 P95 延迟（门槛 ≤ 3s），超标触发降级 |
| R3 | 国内调用智谱 API 的网络稳定性（超时/连接失败/DNS） | 技术/网络 | **高** | 对话中断、用户体感差 | 配置连接/读取超时阈值 + 有限重试；失败自动降级本地规则；沿用已解决的本地 ASR（8010）与神经 TTS 规避语音侧网络错误；记录失败率并告警 |
| R4 | 词库/语料涉及 CC 版权（尤其 NC 非商业限制），商业化受限 | 法律/合规 | **高** | 商业化受阻、需下架重做、法律风险 | 语料以原创或 CC0/可商用来源为主；建立来源与许可证可审计台账；NC 素材仅用于内部验证；商业化前完成版权审计（PM 为合规担责，内容执行） |
| R5 | 输入流语料难度标注主观性强，i+1 分级不准 | 质量 | **中** | 可理解输入失效，习得效果打折 | 制定 CEFR 标注规范与校准样例；双人交叉标注 + 测试抽检；以词频/句长等量化指标辅助；可理解性门槛 ≥ 95% 由内容自评 + 测试验证 |
| R6 | 测试环境浏览器音频兼容性差异（音频播放/语音输入） | 技术/兼容 | **中** | 音频不可用、语音输入断裂 | 优先 Chrome/Edge；不支持浏览器提供文字兜底与明确提示；音频预生成 MP3 规避实时合成依赖；神经语音（edge-tts）避免字母朗读 |
| R7 | LLM 输出不稳定：重述可能过度纠错或漏纠 | 质量 | **高** | 误导学习者，损害核心竞争力 | prompt 明确约束"不打红叉、不过度纠错、保留原意、顺着语义自然接话"；建立 ≥ 6 类语法错误评测集与回归测试；正确率 ≥ 95% 门槛；人工抽检与反馈通道；与降级模式对照校验 |
| R8 | 契约 v2 定义不清或中途变更，导致前后端返工 | 管理/技术 | **中** | 联调返工、进度延误 | M5 冻结契约并交叉评审；变更走书面流程并评估影响；前后端以契约为唯一依据、字段一致性清单逐字对齐 |
| R9 | 内容产能不足，分级语料篇数不达标 | 资源 | **中** | 输入流覆盖不足，B2 目标落空 | 模板化生产 + 提前排期；优先级 A2 → B1 → B2；PM 跟踪篇数进度，不足时协调总指挥调配资源 |
| R10 | 三波并行导致接口/数据字段 v1 与 v2 混用偏差 | 技术 | **中** | 联调阻塞、数据错乱 | 架构契约 v2 为唯一来源；字段一致性清单逐字核对；M5 评审后再开工；测试将契约一致性纳入验收 |

## 7. 沟通与汇报机制

### 7.1 三波汇报节奏（面向"上级"）

| 波次 | 里程碑 | 汇报时点 | 汇报形式 | 汇报重点 |
|------|--------|----------|----------|----------|
| 第一波 | M5 | 契约冻结后 | 文档评审 + 简报 | A+B 双主线拆解、量化目标（A1–A5/B1–B5）、架构契约 v2、风险清单、降级与合规方案 |
| 第二波 | M6 | 并行实现完成后 | 可运行演示 + 周报 | 任意错句重述效果（LLM/降级双态）、输入流三级语料与音频演示、指标达标情况 |
| 第三波 | M7 | 验证交付后 | 独立测试报告 + 验收报告 | 独立 QA 结论、缺陷收敛、端到端联调结果、交付清单、后续（B2 真题）建议 |

- **三波汇报原则**：每波完成即"演示 + 书面"双输出，先展示可运行证据，再附文档与数据；对上汇报一律使用可验证证据（demo、测试报告、指标），避免空泛描述。
- **口径纪律**：涉及学习效果与重述质量时明确区分"内部评测"与"第三方验证"，如实标注 LLM/降级模式，不夸大。

### 7.2 周报模板

```
【呀呀法语 · 阶段二周报】第 N 周（YYYY-MM-DD ~ YYYY-MM-DD）
1. 本周进展
   - 里程碑状态：M5 / M6 / M7（进行中 / 已完成 / 延期）
   - 已完成工作包：（对应 WBS 编号，如 3.1 GLM 重述接入）
   - 双主线指标：主线 A（覆盖率/正确率/降级）、主线 B（篇数/标注/音频）
2. 关键成果 / 演示：（链接或说明）
3. 风险与问题
   - 新增风险：（编号 + 简述）
   - 阻塞项：（需谁决策 / 支持）
4. 下周计划：（工作包 + 交付物）
5. 需上级支持 / 决策事项：（如有）
```

### 7.3 升级路径

```
团队成员 → PM（汇总与初判）
        → 架构师（技术可行性 / 契约争议）
        → 总指挥 team-lead（决策 / 资源 / 范围变更）
        → 上级（阶段汇报与重大事项）
```

- **升级触发条件**：P0 缺陷、里程碑预计延期超过 3 天、范围变更、合规风险（R4）、成本/延迟超阈值（R2）、key 缺失或额度耗尽（R1）、核心功能不可用（R1/R3）。
- **升级时限**：触发后 24 小时内上报，紧急事项（如 P0、key/额度致功能不可用）即时上报。

## 8. Definition of Done（完成判定标准）

一个任务 / 工作包 / 里程碑被标记为"完成"，须同时满足以下全部条件：

1. **交付物齐备**：承诺的文档、代码、接口、界面、语料、音频等交付物全部产出并存放于约定路径。
2. **验收标准达成**：对应 WBS 或里程碑的验收标准逐条满足，有可验证证据（演示、测试报告、接口响应、指标数据）。
3. **量化指标达标**：主线 A（A1–A5）与主线 B（B1–B5）相关指标均有证据支撑，重述覆盖率 ≥ 90%、正确率 ≥ 95%、降级 100%、语料合计 ≥ 18 篇等门槛达成。
4. **质量达标**：代码可运行、无阻断性缺陷（P0 = 0）；后端测试覆盖率达标；契约零偏差。
5. **独立测试报告**：阶段二验收的测试报告须由测试角色**独立出具，非开发自报**——这是硬性标准，缺此不得进入 M7 验收、不得标记完成。
6. **评审通过**：涉及文档/契约/接口的交付物经相关角色（架构师、PM、总指挥）评审确认；文档与实现一致。
7. **合规确认**：语料/词库已标注来源与许可证，无已知 CC 非商用违规；`.env.example` 存在且仓库中不含真实 key。
8. **风险更新**：风险登记册中与本任务相关条目状态已更新。
9. **汇报完成**：已完成对相应对象（PM / 总指挥 / 干系人）的成果汇报。

> 未满足上述任一条件，任务保持"进行中"，不得标记完成。总指挥对阶段二最终交付拥有验收签署权。
