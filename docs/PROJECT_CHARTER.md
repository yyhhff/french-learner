## 1. 项目章程

### 1.1 愿景（一句话）

> **让中文用户像婴儿一样自然地习得法语，以可负担的成本达到 B2（外派可用）水平。**

### 1.2 产品理念

- **婴儿的体验**：可理解输入、先听后说、情境化内容、重述式纠错（recast）、低情感过滤。
- **成人的引擎**：CEFR 定位、FSRS 复习、AI 诊断、B2 考级专项。
- **考级的靶心**：以 B2（DELF B2 / TCF）为能力终点与验收锚点。

### 1.3 目标（B2 量化）

将抽象的"B2"拆解为可度量、可验收的目标：

| 目标编号 | 目标描述 | 量化指标 |
|----------|----------|----------|
| G1 | 日常交流无障碍 ≈ B2 | 在熟悉的生活/工作场景中就日常与抽象话题进行连贯对话，口语任务完成度 ≥ 80%（内部评测集），达到 CEFR B2 可理解性与流利度门槛 |
| G2 | 词汇量 ≈ 6500 | 核心词库覆盖 A1–B2 约 6500 词（基线词库 6900 词 A1–C1，取 B2 及以下部分），高频词掌握率 ≥ 85% |
| G3 | 外派可用（B1–B2） | 完成 4 类核心场景（点单/闲聊/问路/就医）与职场场景训练，外派情境沟通任务成功率 ≥ 80% |
| G4 | 重述式纠错为核心差异化 | 用户错句 100% 由 AI 以自然重述回应，零"红叉式"否定反馈；重述正确率 ≥ 95% |
| G5 | 学习闭环可运转 | 对话 → AI 诊断 → 自动制卡 → FSRS 复习 → 能力画像 全链路打通，闭环可用率 100% |

### 1.4 成功标准

1. **功能成功**：三波 MVP（文档 / API 后端 / Web 前端）全部通过各自验收标准，集成联调后端到端跑通"语音输入 → 重述纠错 → 制卡 → 复习"主链路。
2. **体验成功**：核心差异化（重述式纠错）在演示与真实 API 两种模式下均表现自然，用户无被否定感。
3. **质量成功**：关键路径无阻断性缺陷（P0=0），API 契约与前端调用零不一致，后端单元测试覆盖率达标。
4. **交付成功**：M0–M4 里程碑按期达成，交付物齐备且可独立验收，章程与架构契约、代码三者一致。
5. **合规成功**：词库版权来源清晰，商业化前无 CC BY-NC-SA 商用违规风险；异常与降级路径完备。

## 2. 范围界定

### 2.1 In Scope（本期范围内）

本期以"纵向切透重述式 AI 口语陪练"为唯一尖刀，架构按完整闭环铺开，分三波交付：

| 波次 | 名称 | 主要内容 |
|------|------|----------|
| 第一波 | 规划与契约 | 项目章程、架构契约（API 数据模型、接口约定、状态机）、任务分解与里程碑基线 |
| 第二波 | API 后端 | FastAPI 服务、SQLite 数据持久化、CEFR 定级、场景词库数据管线、重述生成接口、FSRS 复习接口、AI 降级策略 |
| 第三波 | Web 前端 | 原生 JS 应用、4 场景对话界面、重述纠错交互、浏览器 Web Speech API 语音输入、FSRS 复习卡片界面 |
| 集成 | 集成联调与交付 | 前后端契约对齐、端到端主链路联调、缺陷修复、验收与交付 |

### 2.2 Out of Scope（本期范围外，留待后续）

| 范围外项 | 说明 | 留待阶段 |
|----------|------|----------|
| C1 及以上能力训练 | 终点为 B2，C1/C2 不在本期目标 | 后续产品阶段 |
| DELF B2 / TCF 真题冲刺与考级专项 | 靶心为 B2，但真题与专项题库为独立大工程 | 路线图阶段 4 |
| 移动端原生 App / 小程序 | 本期为 Web 形态 | 后续平台阶段 |
| 真实付费 AI 账号体系与计费 | 本期以 API key 调用 + 降级方案为主，不做用户付费、订阅与计费系统 | 商业化阶段 |
| 场景短视频 i+1 可理解输入流 | 输入流为独立模块 | 路线图阶段 3 |
| Whisper 自部署 / TTS 自研 | 本期以 API 调用与浏览器能力为主，自部署留待成本/合规评估后 | 后续优化 |
| 多语言 / 其他语种扩展 | 仅法语 | 远期 |

## 6. 风险登记册

| 编号 | 风险描述 | 类别 | 等级 | 影响 | 缓解措施 |
|------|----------|------|------|------|----------|
| R1 | 开源词库多为 CC BY-NC-SA，含非商业（NC）限制，直接商用将构成授权违规 | 法律/合规 | **高** | 商业化受阻、需下架重做词库、品牌与法律风险 | 基线词库仅用于原型与内部验证；商业化前换用 CC0/可商用授权词源或取得原作者授权；在数据管线中记录每个词源的许可证与来源，建立可审计台账 |
| R2 | LLM/ASR/TTS 推理 API 按量计费，用户规模增长后成本失控 | 成本 | **高** | 运营成本超预算、单位经济模型不成立 | 设置用量配额与预算告警；高频结果缓存；短对话先用轻量模型；保留本地降级桩；定期评估自部署 Whisper/TTS 的成本临界点 |
| R3 | 浏览器 ASR 兼容性差异：Chrome/Edge 可用，Firefox 不支持 Web Speech API | 技术/兼容 | **中** | Firefox 用户无法语音输入，体验断裂 | 前端在不支持的浏览器优雅降级为打字输入并明确提示；优先推荐 Chrome/Edge；在架构中预留后端 ASR（Whisper）作为替代通道 |
| R4 | 学习效果缺乏第三方验证，B2 达标仅有内部评测，可信度不足 | 质量/验证 | **中** | 产品宣称缺乏公信力，用户与上级难以认可成效 | 建立标准化内部评测集与前后测机制；留存学习数据供效果分析；后续引入 CEFR 对标外部测评或第三方研究合作；汇报中如实标注"内部评测"口径 |
| R5 | LLM API key 缺失或不可用，重述功能无法演示/交付 | 技术/依赖 | **高** | 核心差异化功能不可用，联调阻塞 | 架构强制"有 key / 无 key"双态设计；无 key 时使用预置脚本 + 关键词匹配的降级桩（沿用 demo 现有机制）；key 通过环境变量注入，绝不硬编码；明确标注降级模式 |
| R6 | 架构契约定义不清或中途变更，导致前后端返工 | 管理/技术 | **中** | 联调期大量返工、进度延误 | M1 阶段冻结契约并评审；变更走书面流程并评估影响；前后端以契约为唯一依据 |
| R7 | 重述生成质量不稳定，出现错误重述或语义偏移 | 质量 | **中** | 误导学习者，损害核心竞争力 | 设定重述正确率门槛（≥95%）；建立评测用例集与回归测试；保留人工抽检与反馈通道；模型输出加安全约束（prompt 工程） |
| R8 | 关键角色（架构师/后端/前端）人力不足或任务冲突导致里程碑延期 | 资源 | **低** | 里程碑滑期 | 通过 WBS 提前识别关键路径；任务粒度细化便于协调；总指挥统一资源调度与优先级排序 |

## 7. 沟通与汇报机制

### 7.1 分阶段汇报节奏（面向"上级"）

| 阶段 | 汇报时点 | 汇报形式 | 汇报重点 |
|------|----------|----------|----------|
| 立项 | M0 完成 | 简报 | 愿景、第一刀策略、范围边界、里程碑计划 |
| 契约 | M1 完成 | 文档评审 | 架构契约、量化目标、验收标准、风险清单 |
| 后端 | M2 完成 | 演示 + 周报 | API 可用性、双态降级、测试结果 |
| 前端 | M3 完成 | 演示 + 周报 | 核心交互、兼容性、对接进度 |
| 交付 | M4 完成 | 验收报告 | 端到端联调结果、缺陷收敛、交付清单、后续建议 |

- **三波汇报原则**：每波完成即"演示 + 书面"双输出，先展示可运行成果，再附文档与数据；对上汇报一律使用可验证证据（demo、测试报告、指标），避免空泛描述。
- **汇报口径**：涉及学习效果时明确区分"内部评测"与"第三方验证"，不夸大。

### 7.2 周报模板

```
【呀呀法语 · 周报】第 N 周（YYYY-MM-DD ~ YYYY-MM-DD）
1. 本周进展
   - 里程碑状态：M_（进行中/已完成/延期）
   - 已完成工作包：（对应 WBS 编号）
2. 关键成果/演示：（链接或说明）
3. 风险与问题
   - 新增风险：（编号 + 简述）
   - 阻塞项：（需谁决策/支持）
4. 下周计划：（工作包 + 交付物）
5. 需上级支持/决策事项：（如有）
```

### 7.3 升级路径

```
团队成员 → PM（汇总与初判）
        → 架构师（技术可行性/契约争议）
        → 总指挥 team-lead（决策/资源/范围变更）
        → 上级（阶段汇报与重大事项）
```

- **升级触发条件**：P0 缺陷、里程碑预计延期超过 3 天、范围变更、合规风险（R1）、成本超预算（R2）、核心功能不可用（R5）。
- **升级时限**：触发后 24 小时内上报，紧急事项即时上报。

## 8. Definition of Done（完成判定标准）

一个任务/工作包/里程碑被标记为"完成"，须同时满足以下全部条件：

1. **交付物齐备**：承诺的文档、代码、接口、界面等交付物全部产出，并存放于约定路径。
2. **验收标准达成**：对应 WBS 或里程碑的验收标准逐条满足，有可验证证据（演示、测试报告、接口响应）。
3. **质量达标**：代码可运行、无阻断性缺陷（P0=0）；后端测试覆盖率达标；契约一致性校对通过。
4. **评审通过**：涉及文档/契约/接口的交付物经相关角色（架构师、PM 或总指挥）评审确认。
5. **合规确认**：涉及词库/数据的交付物已标注来源与许可证，无已知版权违规。
6. **文档同步**：README、架构契约、本章程等相关文档与实际实现保持一致，无过期描述。
7. **风险更新**：风险登记册中与本任务相关的条目状态已更新。
8. **汇报完成**：已完成对相应对象（PM / 总指挥 / 干系人）的成果汇报。

> 未满足上述任一条件，任务保持"进行中"，不得标记完成。总指挥对最终交付拥有验收签署权。
