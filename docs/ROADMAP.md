# 呀呀法语 · 建设里程图（面客版）维护说明

> TASK-0059 建立。面向用户展示「大版本主题闭环 + 点亮」的路线图，入口在前台「🗺️ 路线图」Tab。

## 唯一维护点

版本定义全部写在后端 `backend/app.py` 的 **`ROADMAP_DEFS`** 常量里（一个列表，按展示顺序排列）。
前端只读 `GET /api/roadmap` 下发的版本数据，**不改前端、不改数据库**。

### 点亮一个新版本（3 步）

1. 打开 `backend/app.py` 找到 `ROADMAP_DEFS`。
2. 把目标版本的 `status` 从 `planned` 改为 `done`，并把 `date` 从 `None` 填成完成日期（如 `"2026-11-25"`）。
   若该版本正在做、想提前高亮，用 `status="active"`（`date` 可为 `None`）。
3. **重启服务**（常量在进程内，无热加载）：`python -m uvicorn app:app --port 8001` 或用 `start.bat`。

刷新前台「路线图」Tab 即见点亮。

### 单个版本字段

| 字段 | 含义 | 取值 |
|------|------|------|
| `version` | 版本号 | 字符串，如 `"v2.1"` |
| `title` | 面客短标题（有温度，非技术名） | 如「明天还想来」 |
| `theme` | 主题一句话 | 如「留存深化」 |
| `status` | 状态 | `done`（点亮）/ `active`（进行中高亮）/ `planned`（灰态） |
| `date` | 点亮日期 | `"YYYY-MM-DD"` 或 `None`（planned 必须为 None） |
| `desc` | 面客说明（温和、不施压） | 一句话 |
| `features` | 该版本闭环功能清单 | 字符串数组 |

## 大版本划分原则（新增版本时遵守）

1. **一个大版本 = 一个完整主题的闭环功能**，不是零散提交的堆叠。用户能用它完成一件完整的事。
2. **面客语言**：标题/说明写用户能感知的价值（「会说话的开始」），不写内部术语（「重述式纠错 API」）。
3. **三态语义**：done 点亮（含日期+功能）、active 温和高亮（正在做）、planned 灰态（无日期、不施压）。文案禁「落后/未达成」。
4. **版本顺序**：按 `ROADMAP_DEFS` 列表顺序展示，新增追加在末尾；如要插入到中间，直接调整列表顺序即可。
5. **口径对齐**：`GET /api/roadmap` 的 `done_count` = `status=="done"` 的条数，`current_version` = 首个 active，无 active 时取最后一个 done。
