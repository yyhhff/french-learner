## 1. 问题定性：五件事，一个根因

用户说的五件事（学了哪些词 / 如何定期复习 / 有哪些成就 / 如何吸引主动用 / 缺做题外的细粒度水平衡量 + 要有感知度）不是五个孤立缺口，而是**同一根因的五个表征**。

**根因：无学习状态闭环。** 学习行为发生后无法"被看见"——写了对话读不回、展示数字是假值、SM-2 引擎空转只做假计数。用户无法看见自己，就没有回访动机。

| 表征 | 现状事实 | 根因归属 |
|---|---|---|
| ① 学了哪些词 | 生词卡已落库但无聚合视图，"我的词库"不可回顾 | 行为未可视化 |
| ② 如何定期复习 | srs.py 有 SM-2、review_logs 有 next_due，但无到期队列查询/无触达 | 有引擎无调度 |
| ③ 有哪些成就 | 无成就体系；xp/streak 是种子假值 | 假数据冒充成长 |
| ④ 如何吸引主动用 | 无 onboarding、无进度可见、无回访钩子 | 无正反馈飞轮 |
| ⑤ 细粒度水平衡量 + 感知度 | 只有一次性 12 题定级静态标签，无持续多维趋势感知 | 静态标签≠成长 |

**闭环模型（方案总纲）**：
`学习行为 → 真实记录 → 可回顾(我的成长) → 智能调度(复习到期) → 温和不打扰触达 → 微小正反馈(成就/趋势) → 再学习`。五个表征对应闭环上的五个断点。

## 2. 目标与克制原则

**总目标**：让每一次学习都「留得下、看得见、叫得回、有奔头」。延续"像婴儿一样自然轻松"、低情感过滤，所有机制以"陪伴"而非"考核"呈现。

| 做 ✅ | 坚决不做 ❌ |
|---|---|
| 真实数据（宁可显示"0/刚开始"，不显示假值） | 种子写死的假数字（1280/12 清零） |
| "我的成长"可视化、趋势与进步感知 | 红叉、扣分、排名、好友对比 |
| 温和到期提醒（产品内自然节点） | 打卡羞辱、断签惩罚、"你落后了" |
| 鼓励式轻成就（描述行为不评价优劣） | 勋章墙攀比、积分兑换、排行榜 |
| ≤3 步可跳过的轻引导 | 强制引导、必须完成才能用 |
| 多维微进度（听说读写词汇趋势） | 用绝对等级给用户贴标签施压 |

**贯穿红线**：所有面向用户的数字必须来自真实行为；文案走"可以/随时/慢慢来"口径，零"必须/逾期/落后/断签惩罚"。

## 3. 关键取舍（总指挥裁决建议，待确认）

### 3.1 持久化路径 → 服务端 SQLite 为主 + localStorage 仅做离线草稿（推荐）

- **纯 localStorage**：零后端改动，但清缓存即丢、换设备归零，且复习调度需跨会话时间计算，放前端会与后端 `review_logs` 形成两份真相——**不解决用户抱怨**。
- **服务端 SQLite 为主**：与已有 9 表同库同源、复习调度天然在服务端算、隐私可控。本项目已有 `CREATE TABLE IF NOT EXISTS` 幂等建表模式，边际成本低。
- **推荐混合**：真实进度（对话历史/生词/复习/成就/画像）**服务端 SQLite 为唯一真相**；localStorage 仅保留两类离线草稿——①未提交的输入文本 ②网络失败待重发的答题/对话（带时间戳，恢复后对账，服务端为准）。
- **反过度设计**：本轮不引入账号系统、不加依赖，`user_id` 仍默认 1；但**所有新表带 user_id、所有查询过滤 user_id**，为未来鉴权零成本铺路。`get_profile()` 的 `due_cards_count` 查询缺 user_id 过滤，一并修正。

### 3.2 水平画像数据源 → 从已有行为派生，不重造考试

把已有行为聚合成技能画像，**不是再加一套测验**：
- `dialogue_turns`：按场景 cefr_level、`is_correction`（GLM 重述标记，弱信号）派生口语流利度/语法准确度
- `word_cards`：按 cefr_level + pos 分布派生词汇量/层级
- `review_logs`：repetitions/ease_factor/interval 派生记忆稳固度
- `attempts(kind=placement)`：初始 CEFR 基线锚点
- `attempts(kind=exam)` 的 items[].type + 考卷 section：阅读/词汇语法/听力/写作/口语的直接信号

画像是"练习侧写"，**非官方 CEFR 判定**；与定级/考级一样温和、非认证口径（产品语义以 PM 方案为准）。

## 4. 产品方案（PM 交付，6 项）

> 每项含用户场景、交互形态、文案口径、验收标准；字段/端点见 §5 技术方案。

### A. 学习进度持久化 +「我的成长」视图
- **场景**：学了几天想知道积累了什么；刷新或下次打开进度还在。
- **交互**：新增「我的成长」入口，聚合 5 张卡——词汇（累计/本周新增）、对话（累计轮数/场景）、阅读（已读篇数/等级分布）、复习（待复习数/累计次数）、水平画像（见 E）。模块内加微状态（词卡"已收藏"、阅读卡"已读"）。
- **记什么/何时记**：生词在收藏时记词+来源+时间，复习时更新熟悉度；对话每轮记场景+轮次+时间（**不存全文到前端**，见隐私）；阅读每篇完成记篇目+等级；复习记卡片+结果+下次到期；活跃按真实行为更新连续天数。
- **文案**："你走过的每一步都在这里～"；空态"从第一段对话开始，慢慢积累就好"。
- **验收**：① 刷新后 5 类数据 100% 保留；② 展示数字 100% 来自真实行为、假值清零；③ 空态温和无"0 恐慌"；④ 首次对话后成长页至少 1 条真实记录。

### B. 复习机制（把 SM-2 真正用起来）
- **场景**：收藏的词几天后"自己回来找我"，不靠自觉。
- **交互**：成长页「今日待复习 N 个」→ 点入复习小流（复用现有词卡复习交互）；每张卡按 SM-2 算下次到期，到期者进今日队列；在对话/阅读结束的自然节点温和提示，**不弹窗、不推送**。
- **文案**："有 N 个词想再见你一面～" / "今天温故了 N 个词，很棒"；禁用"逾期/必须/遗忘/再不复习就忘了"。
- **验收**：① 到期计算符合 SM-2（答对/答错间隔变化有可测用例）；② "今日待复习"数 = 到期卡片数，误差 0；③ 复习结果更新下次到期；④ 无到期时温和空态；⑤ 全程无红叉、无强制弹窗。

### C. 成就系统（轻量、鼓励式、非攀比）
- **场景**：努力被看见，但不被比较、不被胁迫。
- **交互**：成长页成就墙（小徽章，**无排行榜**）；解锁时轻 toast + 徽章点亮，不打断学习；**累计制**——断签不清零、不倒退。

| 成就 | 解锁时机（可测） | 文案 |
|---|---|---|
| 初来乍到 | 首次对话/阅读/定级任一 | "迈出了第一步，很好" |
| 词汇萌芽 | 收藏第 1/10/50 词 | "词库里冒出了小芽" |
| 温故知新 | 完成第 1/10 次复习 | "和老朋友又见了一面" |
| 阅读小径 | 读完第 1/5/21 篇 | "走过了 N 篇短文" |
| 开口说 | 首次使用口语/ASR | "勇敢开口了" |
| 持续陪伴 | 累计活跃 3/7/30 天 | "已在法语里走了 N 天" |
| 阶梯上行 | 参考等级提升 A2→B1→B2 | "你上了一个台阶" |
| 小试身手 | 完成首套模拟卷 | "试了试身手" |

- **验收**：① 每类成就触发条件 100% 可测；② 无排名/攀比/断签惩罚元素（走查零命中）；③ 解锁不打断学习流；④ 断签后成就不清零。

### D. 留存激励（吸引主动回来）
- **场景**：无外部压力，靠"成长可见 + 每天一点点 + 温和召唤"愿意再来。
- **交互**：成长页「微进步」卡（本周 vs 上周词数/阅读数、等级趋势）；轻量「今日小目标」（读 1 篇 / 复习 3 词 / 对话 1 轮，完成即肯定，不做满勤胁迫）；连续天数仅作正向记录，断了温和召回；打开 app 显示"上次你读到 B1 的一篇，要不要接着？"。
- **文案**："每天一点点，就很好" / "又见面啦，重新开始就好"；禁用"断签/惩罚/落后/未完成"。
- **验收**：① 打开可显示基于真实行为的"接着上次"钩子；② 断签文案零负面词；③ 小目标完成有正反馈、未完成无焦虑；④ 连续天数真实计算、跨天规则正确。

### E. 细粒度水平衡量（做题之外的持续感知）
- **场景**：不想只靠一次 12 题贴标签，想知道"听说读写各到哪、在不在进步"。
- **交互**：水平画像页 = 当前参考等级 + 五维微进度（词汇/阅读/听力/口语/写作，进度条 + 趋势箭头 ↑→，**不显示绝对等级施压**）+ 近 30 天趋势；阅读卡显示"这篇对你刚好（i+1）"；用"过去两周 A2 词占比下降、B1 上升"这类**变化**说话。
- **边界**：画像只在**展示层**做，不改 `cefr_level` 本体、不动波一定级/波二考级冻结契约；i+1 可视化与现有 `/api/input/recommend` 的 target_level 一致。
- **文案**："你在慢慢往前走" / "这一维最近有进步"；禁用"你只有 A2 / 未达标"。
- **验收**：① 五维进度全部由真实行为推导、零硬编码；② 趋势时序可见；③ i+1 标签与 recommend 一致不矛盾；④ 完成一次学习后至少 1 维发生**可见变化**（感知度可测）。

### F. 首次引导（≤3 步温和 onboarding）
- **场景**：新人进来不应只见预置场景和 suggestion 列表。
- **交互**：① 欢迎"像婴儿一样慢慢学～" + 开始；② 引导去定级（12 题）但**可跳过**——"先做几题看看，或随便逛逛都行"；③ 一次性气泡点出"对话/阅读/我的成长"三入口（可跳过）。
- **文案**：全程"可以/随时/都行"，无"必须/请先完成"。
- **验收**：① 3 步内完成、任意可跳过；② 只出现一次（可"重新看看"）；③ 引导后三入口可达；④ 文案零强制词。

## 5. 技术方案（架构师交付，字段名【待冻结】）

### 5.1 学习进度持久化（服务端为唯一真相）
- **对话历史**：复用 `dialogue_turns`，不建新表。新增 `db.list_dialogue_history(user_id, scene_id?, limit, before_id?)`【待冻结】，按 id 倒序取、前端反转；端点 `GET /api/chat/history`（Query: scene_id?, limit?, before_id?）→ `{items: DialogueTurn[], has_more: bool}`。初次进入场景先拉历史，无则用 start_dialogue 种子对话。**彻底解决"写了读不回"**。
- **生词/复习状态**：完全复用 `word_cards` + `review_logs`，不建新表，仅补查询。
- **成就**：新建 `achievements` 表：`id / user_id / code / earned_at / detail_json`，`UNIQUE(user_id, code)` 保证幂等，索引 `(user_id, earned_at DESC)`。
- **水平画像**：新建 `skill_profile` 表：`user_id / skill / level_estimate / score / trend / updated_at`，主键 `(user_id, skill)`；另建 `skill_events` 事件流水 `id / user_id / skill / delta / source / source_id / created_at`，支持增量与全量重建（算法调整后可一键 rebuild，防数据污染）。
- **XP/streak**：不再信任 seed 假值。xp 仅由真实行为累加（对话轮、复习卡、完成考级、解锁成就——分值以 PM 为准）；streak 由 `update_user_activity()` 按天更新，**起点归零重算**。

### 5.2 复习调度（把 SM-2 真正跑起来）
- 复用 `srs.schedule()` 与 `review_logs.next_due`，不重写算法。
- 新增 `db.list_due_reviews(user_id, now, limit, offset)`：`SELECT ... FROM review_logs r JOIN word_cards c ON r.card_id=c.id WHERE c.user_id=? AND r.next_due<=? ORDER BY r.next_due, r.id LIMIT ? OFFSET ?`，出参复用 WordCard + review_state。
- 端点 `GET /api/review/due`（limit?, offset?）→ `{items: DueCard[], total, today_count}`【待冻结】；默认 limit=10、无倒计时、无红点施压。复习成功走既有 `POST /api/cards/{id}/review`（契约不变），`srs.schedule()` 自动推进 next_due。
- 修正 `get_profile().stats.due_cards_count` 补 user_id 过滤，与新队列口径一致。

### 5.3 成就系统
- **判定源**：只从已落库真实事件判定，不从前端上报（防伪造）。事件源 = add_dialogue_turn 计数、create_card 计数、review_logs 达标记、attempts 完成、streak 值。
- **时机**：5 个提交类端点成功后统一调 `achievements.evaluate(user_id, event)`【待冻结】，返回本次新解锁列表写库（INSERT OR IGNORE 靠唯一约束去重）+ 计入 XP。
- **幂等**：UNIQUE(user_id, code) + INSERT OR IGNORE；code→规则放服务端常量，不下放判定逻辑到前端。
- **端点** `GET /api/achievements` → `{items:[{code,name_zh,desc_zh,earned_at,unlocked}], unlocked_count}`【待冻结】；未解锁也返回灰态，给"下一个目标"牵引感。

### 5.4 水平画像（增量 + 趋势 + i+1 衔接）
- **维度**【待冻结，与 PM 对齐】：`vocabulary / grammar / listening / reading / speaking / fluency / memory`（7 维，覆盖考级 section 与对话/SRS 信号）。每维输出 `level_estimate` / `score`(0-100) / `trend`(up/flat/down) / `updated_at`。
- **增量算法**：每次真实事件写一条 skill_events（source ∈ placement/exam/chat/review/input）；`score_new = (1-α)*score_old + α*event_score`，α 按 source 可信度（exam 高、chat 弱）；trend 由最近 N 条线性斜率判定；level_estimate 由 score 映射档位（阈值【待冻结，以 PM 为准】）。提供 `rebuild_profile(user_id)` 全量重算。
- **i+1 衔接**：`GET /api/profile` 增 `skill_profile` 字段（或独立 `GET /api/profile/skills`）；recommend 保留原 cefr_level 驱动逻辑，画像仅作**同档内篇目排序权重**（弱维度优先）——零回归且更个性化。

### 5.5 首次引导与状态迁移（关键：不能让假数据继续骗人）
- **新用户（空库）**：seed 的 `users.xp=1280/streak=12` 改为 0，或明确标记 is_demo 只展示"开始你的第一段对话"。用户第一次看到的必须是真实 0 起点。
- **老用户（已有假数据的本机库）**：一次性迁移 `migrate_demo_progress()`【待冻结】：仅当检测到纯演示值（xp==1280 且 streak==12 且无真实事件流水）时清零并写迁移标记；有真实行为的库绝不重置。"宁可清零重来，不可假数续命"。
- **前端状态**：state 增 `progress` 子树（skills/achievements/due/history），启动并行拉 4 端点；FALLBACK_PROFILE 降级为"网络不可用时空壳"，标注"离线暂不可查看进度"，不再拿 1280/12 冒充。
- **对账**：定级/考级本地缓存（placement_result）保留，但以服务端 attempts 为准——启动发现本地有结果而服务端无对应 attempt 时清掉本地标记。

## 6. 零回归与风险

- **零回归清单**：现有 21 端点路径/入参/出参 data 不变；`/api/chat`（history 入参、ChatResult 4 字段）、`/api/profile` 只增不改、`/api/cards/{id}/review` 走 srs.schedule 契约不变、`attempts` 表不改、`users` 表只增字段不改旧列；`ai.py`/ASR 完全不动；`requirements.txt` 仍两行、零新依赖。
- **风险1 隐私**：对话内容最敏感——历史端点必须带 user_id 过滤、限制 limit（默认 50、上限 200）、禁止无鉴权批量拉取；上账号时优先给它加鉴权。前端成长页只存元数据、不展示对话原文。
- **风险2 迁移**：清零演示值是破坏性动作，只在空库/纯演示库触发；QA 用临时库隔离验证两种库。
- **风险3 性能**：画像聚合/成就判定同步做会拖慢提交——"提交时写事件流水 + 懒计算画像"，下次拉取时再算，提交响应只回新解锁成就名。
- **风险4 一致性**：服务端为准，localStorage 草稿仅在提交失败时保留并按时间戳回填。
- **本轮不做**：多用户账号/登录、FSRS 替换 SM-2、真实版权真题、画像官方 CEFR 认证口径、跨设备云同步。

## 7. 分期与验收（P0 为最高价值薄片）

| 期 | 解决痛点 | 交付内容 | 用户可见变化（可验收） |
|---|---|---|---|
| **P0 信任起点 + 持久化闭环** | ①学了什么 ④可视化回访 ⑤画像起步 | 服务端持久化底座（对话历史读回、生词/复习/活跃真记录、假值清零）+「我的成长」v1（含真实"今日待复习 N 个"）+ ≤3 步 onboarding + 水平画像 v1（静态五维） | 刷新后对话不丢；数字是真的、新用户从 0 起；新人 3 步上手；能看到待复习数与五维轮廓 |
| **P1 感知度 + 调度跑通** | ②定期复习 ③成就 ④留存深化 | SM-2 真正到期调度 + 成就系统 + 留存激励（今日小目标/断签不惩罚/接着上次）+ skill_events 接入 5 类事件 + 前端 state.progress 初始化 | 到期词自动回来；成就点亮；打开即有"接着上次"钩子；连续 3 天 streak 真实 +1；画像随行为可见变化 |
| **P2 精细化 + 演进准备** | ⑤画像深化 + 体验细节 | 五维趋势与 i+1 可视化 + 骨架屏/操作进度感知 + 移动端三栏验证优化 + localStorage 草稿对账 + user_id 隔离审计 | 看到趋势箭头与"刚好 i+1"标签；加载不再空白；手机布局好用；断网输入恢复正确 |

**P0 为何这样切**：用户最痛的是"学完什么都没留下、看不见自己"。持久化底座是所有后续机制（复习调度/成就/趋势/画像）的共同前提——不先沉淀真实数据，SM-2 没有到期源、成就没有触发源、趋势没有数据源。因此 P0 优先打通"记录 + 看见 + 上手"，用现成的复习计数先做可见化，把真正的 SM-2 调度放 P1。
